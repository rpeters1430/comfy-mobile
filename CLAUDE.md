# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A mobile-first FastAPI dashboard ("Image Studio Mobile") that runs in Docker on a NAS and proxies a ComfyUI instance on another machine. The phone UI is a static page (`app/static/index.html` + `style.css` + `app.js`; visual rules in `DESIGN.md`); all ComfyUI access goes through the backend, which never exposes ComfyUI directly to the browser.

## Commands

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v          # full suite
python -m unittest tests.test_workflow_conversion -v
python -m unittest tests.test_workflow_conversion.ConversionTests.test_connected_graph_and_prompt
python -m compileall -q app                      # CI also runs this as a syntax check
node --test 'tests/*.test.js'                   # front-end helpers in static/*.js (mobile-tools, presets, adviser, lora-compat)
ruff check app tools tests                       # CI lint: pyflakes rules only (ruff.toml)
npm install --no-save playwright && npx playwright install chromium && node tests/browser-mobile.cjs   # CI browser smoke test
docker build -t comfy-mobile .
```

CI (`.github/workflows/`) runs the unit tests on 3.14 and 3.15, ruff, and the Playwright smoke test. The image build is scanned with Trivy before it is pushed and fails on any fixable HIGH/CRITICAL finding, so a vulnerable Python pin blocks publishing until it is bumped.

`tests/test_bundled_workflows.py` asserts there are exactly 33 files in `workflows/` (update the count if you add or remove one) and, when `fixtures/object_info.bundled.json` is committed, that each converts and validates against it. Otherwise that test is skipped.

Running locally: `app/main.py` uses flat imports (`from workflow_sync import ...`) and serves `/app/static/index.html` by absolute path, because the Dockerfile copies `app/` to `/app` and runs `uvicorn main:app` from there. Tests import the modules as `app.workflow_*`. Nothing imports `main.py` in tests, so keep logic in the other `app/*.py` modules where it can be tested. A module that imports a sibling tries the package import first (`from app.x import y` or `from .x import y`) and falls back to `from x import y` on `ImportError` so it works both ways; copy that pattern when adding cross-module imports. Running outside Docker: `cd app` and set the env vars plus `STATIC_DIR=static` (it defaults to the Docker path `/app/static`).

Configuration is env-only: `COMFYUI_URL`, `STUDIO_TOKEN` (required, or every endpoint returns 401), `WORKFLOW_DIR` (bundled, mounted read-only), `WORKFLOW_SYNC_DIR` (writable), `DATA_DIR` (writable by uid 1000; job records, thumbnails, push keys; if it is missing those features are off), `PUSH_CONTACT` (VAPID `mailto:`), `MODELHARBOR_URL` + `MODELHARBOR_TOKEN` (optional; LoRA trigger words and strengths), `ADVISER_PROVIDER`/`ADVISER_MODEL`/`ADVISER_BASE_URL`/`ADVISER_API_KEY`/`ADVISER_VISION_MODEL` plus `OLLAMA_URL` or `LEMONADE_URL` plus `SEARXNG_URL` (optional AI adviser and its web research; `ollama` and `lemonade` are local providers that allow plain HTTP and an optional key, the hosted ones need HTTPS and a key), `STATIC_DIR` (local runs only).

Design notes live in `docs/` (`adviser.md`, `security-review.md`, `roadmap.md`, `workflow-sync-plan.md`); the README carries release notes.

## Core server and phone

- **`main.py`**: every `/api/*` route calls `auth()` (constant-time Bearer token compare) first. `request()` is the only ComfyUI HTTP helper. On an HTTP error it returns 502 and passes through only ComfyUI's JSON `error`/`node_errors` fields, never raw HTML. It raises `ComfyOffline` (an `HTTPException` subclass) only for connect errors (see held jobs). ComfyUI endpoints with empty bodies need `request(..., expect_json=False)`.
- **Compression:** `Compress` (GZipMiddleware) skips paths ending `/view`, `/preview` and `/stream`, so Range requests and streams pass untouched. `get_object_info` hashes the payload and clears `_catalog_inspect_cache` only when it changed.
- **PWA:** `static/sw.js` handles the Web Share Target (`POST /share-target` → Cache Storage → `/?shared=N`), push messages and notification clicks; it never caches the app or API. The server-side `/share-target` route is only a fallback before the worker is installed. Saved prompts and per-device settings live in `localStorage`.
- **Front end:** `static/mobile-tools.js` (`MobileTools`) holds pure data helpers and is loaded before `app.js`; the Node tests cover it. `tests/browser-mobile.cjs` is optional Playwright smoke coverage with API mocks (not part of the dependency-free Node test glob). Tabs come from `TABS`; `?tab=` is used by manifest shortcuts and held-job notifications. The app badge uses `navigator.setAppBadge`.
- **Wake-on-LAN (`wake.py`):** administrator-configured `WOL_MAC` / `WOL_BROADCAST`, UDP port 9, 30-second cooldown. GET/POST `/api/comfy/wake` are authenticated. Never accept client-selected destinations.

## Workflows: sources, sync, conversion

- **Two sources:** bundled files in `WF_DIR` and synced files in `SYNC_DIR`. Synced workflow IDs carry a `synced/` prefix, which `/api/jobs` and `/validate` strip to choose the root directory. `load_workflow` (`workflow_validation.py`) enforces path containment, a `.json` suffix and a 2 MB limit. `MobileTools.preferredWorkflows` hides bundled copies only when the synced copy is runnable, exposing a labelled bundled fallback when sync is broken.
- **`workflow_sync.WorkflowSync`:** PC-to-app downloads only, refreshed every minute and on catalog refresh. Downloads nested saved workflows from `/userdata?dir=workflows&recurse=true&split=false`, validates paths/graphs and size limits, and writes atomically. Prunes stale downloaded JSON only after a completely successful import. Reset clears local workflow JSON/partial files without PC access and writes `SYNC_DIR/.reset` to pause automatic imports across restarts; only a successful manual sync removes the marker. Catalog lists only synced workflows, with no bundled fallback or uploads. Legacy `sync?reset=true` also performs reset. Runs serialize with an asyncio lock.
- **Change notices:** the catalog sends each workflow file's `modified` time (sync only rewrites changed files). The phone shows "updated on PC" until the workflow is opened, and `MobileTools.controlKeys`/`controlChanges` (per device) list what was added or removed since last time; new node groups open with a "new" badge.
- **Formats:** *UI* (LiteGraph JSON with `nodes`/`links`, which is what the bundled `workflows/*.json` are) and *API* (`{id: {class_type, inputs}}`). UI graphs are converted to API format on every catalog, validate and job call, using live `/object_info` from ComfyUI.
- **`workflow_conversion.convert_ui`** fails closed by design: it raises `ConversionError` instead of guessing. It mirrors what ComfyUI's own frontend sends, so check behaviour against real files and ComfyUI source, not intuition:
  - Subgraphs (`definitions.subgraphs`) are inlined first by `_flatten`; inner IDs become `<instance>:<inner>`. Instance `widgets_values` line up with the subgraph's widget-type inputs in order. Nested/bypassed subgraphs fail closed.
  - Widget values map positionally over widget-type inputs in schema order, **including linked ones** (ComfyUI keeps their slot), but not `forceInput` ones, which are sockets with no saved value. A randomize/fixed control slot follows INTs flagged `control_after_generate`, or top-level `seed`/`noise_seed`. V3 `COMBO` uses `options`; a `COMFY_DYNAMICCOMBO_V3` value is followed by its chosen option's sub-widgets, sent as `<combo>.<sub>` keys. `COMFY_AUTOGROW_V3` inputs arrive as `<field>.<name>`. Don't "shift values to fit".
  - Leftover values: `_map_widgets` returns the values no schema input took. `_frontend_widgets` maps known frontend-only widgets (`FRONTEND_WIDGETS`, Power Lora Loader `lora_N` rows) and skips upload buttons and `DISPLAY_WIDGETS`; anything else non-empty raises `ConversionError` naming the node.
  - Mode 4 (bypass) passes through the same-typed input; mode 2 (muted) nodes are dropped along with inputs they feed. Links missing from the links array are restored only when exactly one output and one input claim them.
  - Bare model filenames resolve to a unique subfolder entry. `LoadImage.image` is not validated; jobs fill it (`image_inputs`). List widget values are sent as `{"__value__": [...]}` because ComfyUI reads bare lists as links. Preview nodes with a required socketless widget (ImageCompare) are dropped. Each node gets `_meta.title`, as ComfyUI's frontend does.
- **Prompt injection point:** `bind_prompt` writes `{{prompt}}` into the single top-level prompt field: an unlinked non-negative CLIPTextEncode, a `PrimitiveString(Multiline)` titled "…prompt…" (not negative/prefix/trigger), or an unlinked subgraph input named/labelled `prompt`. None means the workflow takes no typed prompt (auto-caption), which is valid; more than one fails. `workflow_jobs.apply_job` replaces the placeholder, fills uploaded images in `image_inputs` order and overrides `seed`/`noise_seed`.

## Job controls (`workflow_controls`, `node_settings`)

`find_controls` reads the converted graph and `/validate` returns the result as `controls`; `apply_controls` applies a job's choices and only accepts nodes it found, names in ComfyUI's own option lists, and values in range. Model lists use `_options`, which reads V3 COMBO.

- **Models and LoRAs:** `CheckpointLoaderSimple`/`UNETLoader` pickers and existing `LoraLoader(ModelOnly)` nodes. Jobs send `models`, `loras` and `extra_loras`. Extra LoRAs are `LoraLoaderModelOnly` nodes (`mobile_lora_N`) inserted after the single model loader and any LoRAs already chained to it; with more than one model loader, adding is refused. Strength 0 on a `LoraLoader` zeroes both strengths so ComfyUI skips loading it.
- **LoRA Manager loaders:** `<lora:name:strength>` (or `name:model:clip`) tags in a string primitive feeding a `*LoraManager*` node's `lora_syntax` appear in `loras` as `<primitive>#<index>` with `syntax`; only tags whose file stem matches exactly one installed LoRA. Changing one rewrites that tag (form as written; clip follows when it matched), strength 0 removes it; others stay as written. Active entries of a LoRA Manager loader's `loras` list widget appear as `<node>@<index>` with `widget`; a change sets the entry's name (file stem) and strength, clip follows when it matched, and strength 0 turns it off. `settings_check.manager_loras` reads widget, text and linked `lora_stack` LoRAs, so the checks and the adviser see them.
- **Sampling:** plain `steps`/`cfg`/`sampler_name`/`scheduler` on KSampler-type nodes (`denoise` only on refine passes, i.e. denoise < 0.99); jobs send `sampling`.
- **Image size:** `Empty*LatentImage` nodes with plain width/height, or with width/height linked from a `GetImageSize` (image-to-prompt-to-image workflows; `size_from_photo`, budget from `ImageScaleToTotalPixels.megapixels`, and a job `size` replaces the links); jobs send `size`. The phone picks a shape and keeps the workflow's pixel count. Exact-resolution wallpaper presets also send `fit`: `_apply_fit` puts an optional `ImageUpscaleWithModel` and a lanczos center-crop `ImageScale` in front of every `SaveImage(Advanced)`, so the model renders near its native pixel count and the saved file is exactly the screen size.
- **Video:** `video` for the single video latent (`WanImageToVideo`, `EmptyLTXVLatentVideo` and kin), traced to the workflow's own primitives so linked nodes stay in step: `seconds`/`fps` from a `ComfyMathExpression` `a * b + 1` (`floor` allowed) on the latent's `length`; `width`/`height` from `a` or `a/N` expressions over `PrimitiveInt`s (LTX's half-size first pass), or the latent's plain ints; otherwise `megapixels` of the `ImageScaleToTotalPixels` the photo-sized latent reads (Wan I2V). Jobs send `video: {seconds, width, height, megapixels}`; `_apply_video` checks 1–20 whole seconds, multiples of 8 and 0.2–1.5 MP. The phone's Video section has a length slider (Wan capped at its trained 5 s, or the workflow's own longer default, via `max_seconds`; LTX and others 20 s), resolution × orientation chips for exact-size workflows, and Fast/Standard/High quality chips for photo-sized ones.
- **Skip face detailer:** `detailers` lists `FaceDetailer(Pipe)` nodes whose only used output is the image. A job's `skip_detailers: true` removes them and wires their input image to their consumers (roughly 1–2 minutes saved per face on workflow 02).
- **All other workflow settings (`node_settings.py`):** `settings` has one group per node (title from `_meta.title`) with every unlinked INT/FLOAT/BOOLEAN/COMBO widget, plus multiline STRINGs and string primitives, typed and bounded by the live schema. Fields a dedicated control owns (`_owned`: models, LoRAs, sampler fields, latent size, caption fields, video primitives, negative prompt) and plumbing (`SKIP_FIELD`: seeds, url/path/filename/prefix, device…) are left out; `LoadImage`/`SaveImage`/previews and `mobile_*` nodes are skipped. A node titled `📱 …` is pinned to the top. Jobs send `settings: {node: {field: value}}`, applied first (before detailers are removed). Bundled workflows produce no settings issues; when a field needs special handling, give it a dedicated control instead.

## Auto captions (`workflow_controls`, `caption_review`, `characters`)

- **Caption nodes:** `is_caption_node` matches the known `CAPTION_CLASSES`, or any non-partner node whose class/category mentions caption/Ollama/VLM that takes an IMAGE and returns STRING first (so `JoyCaptionOllamaPrompt` and other new nodes need no code change; Booru Tagger and text-only Ollama nodes don't match). Every unlinked COMBO (validated against ComfyUI's options) and BOOLEAN widget is exposed as `captions` with schema `tips` and a `style` field (`caption_type`/`prompt_style`/`preset`), minus plumbing fields (`CAPTION_SKIP`: keep_alive, seed, url…); jobs send `caption`. The phone labels unknown fields from their names, folds more than 10 switches into "Extra options", and shares the caption model and length across workflows; style and switches stay per workflow, and only switches tapped on the phone (`captionToggles`) override the PC values, so one workflow's "Vulgar slang" can't leak into another.
- **Caption review (`caption_review.py`):** needs exactly one supported VLM node. Builds ancestor-only graphs with PreviewAny sinks for positive/negative text, or replaces those text links for approved rendering and prunes unused dependencies. `/api/jobs` takes `stage: caption|render` and optional `review: {positive, negative}`; `/validate` exposes capability/reason. Fails closed on ambiguity/non-text consumers.
- **Appending words without review:** a job's `caption_suffix` makes `caption_review.append_caption` join words with a `StringConcatenate` node (`mobile_caption_triggers`) onto the single text output that every sampler's positive prompt is encoded from (`trigger_target`, traced upstream through conditioning nodes). That works even with several caption-like nodes, such as JoyCaption plus an Ollama identifier joined by concats; `/validate` reports it as `trigger_words`.
- **Character naming (`characters.py`):** for a single caption node with an unset `character_name` input (JoyCaption via Ollama), a job's `characters: true` adds `Load Booru Tagger` (PixAI v1.0 preferred) + `Booru Tagger` (`mobile_tagger*`, thresholds 0.35/0.45 with best thresholds) on the caption's photo and links `character_tags` into `character_name`, plus a `mobile_characters` PreviewAny the phone shows as "Recognised: …". `/validate` returns `characters` (support/reason). Workflows that already set or wire a name are left alone; an approved caption review prunes the tagger. Fictional characters only: the tagger's Danbooru list, never identification of real people. On by default per workflow ("🎭 Name known characters").

## LoRAs and model families (`lora_info`, `lora_suggest`)

- **Families:** `find_controls` returns `families` (`settings_check.family` labels) for model and LoRA options; families come from the model folder (`SDXL\`, `Pony\`, `SD15\`, `SD2\`, `Krea2\`…), then filename keywords (`sd21`/`v2-1` for SD 2.x). `MobileTools.modelGroups` groups pickers by family, the checkpoint's family first (✓), and lists a file kept loose and in a folder once. LoRA pickers list only the checkpoint's family plus unknown files (`modelGroups(..., only)`), keeping the current pick, and warn on a mismatch.
- **Info:** `GET /api/loras/info` first reads LoRA Manager's `/api/lm/loras/list` on the ComfyUI server (no setup; cached 1 min; Civitai `trainedWords`, base model, and the user's `usage_tips` strength as `weight` with `weight_from: 'loramanager'`). `lora_info.merge` lets its non-empty fields win over ModelHarbor's. It then matches ModelHarbor's `/api/models` records (cached 5 min) to ComfyUI LoRA names by the path under `loras/`, then by a unique file name. Per LoRA it returns Civitai `triggers`, the recommended `weight` (median strength in the creator's example images) and a `family` from Civitai's base model (`settings_check.civitai_family`). For unmatched LoRAs a trigger guessed from training tags (`lora_suggest.profile`) is returned with `guessed: true`. The phone fills unknown families from it. Picking a LoRA sets its strength to the one last used for it on this device, else the recommended weight, else 1.
- **Trigger words:** a LoRA with exactly one trigger has it appended to the prompt (or reviewed caption) on Generate; several triggers are tap-to-add chips. Workflows that write their own prompt get them through `caption_suffix` (above).
- **Auto LoRAs:** `POST /api/loras/suggest` (no AI) profiles each LoRA from ComfyUI's `/view_metadata/loras` (kohya `ss_tag_frequency`, cached per process) plus filename words, weights matches by rarity, and needs a filename word or two tags to match. Only the given family, never speed LoRAs. "Auto-add matching LoRAs" adds up to two per job (not to saved choices) from the prompt or reviewed caption and appends trigger words.
- Under an adviser approval nothing is added: no auto LoRAs, trigger words or wildcards.

## Job lifecycle (`workflow_jobs`, `job_store`, `progress`, `push`, `deferred`)

- **Uploads and outputs:** `/api/uploads` takes a raw PNG/JPEG/WebP body, names it `mobile_<uuid>.<ext>` from magic bytes and forwards it to ComfyUI; jobs only accept those names. `/api/jobs/{id}/outputs` lists files with HMAC-signed `view` URLs (keyed off `STUDIO_TOKEN`, valid 24–30 h) because `<img>`/`<video>` can't send a Bearer header. It only signs files that job produced, and the expiry is rounded to 6 h steps so URLs stay stable and the browser caches them (`immutable`). `/view` passes Range through; `&thumb=1` asks ComfyUI for a WebP copy (`preview=webp;80`, images only). "Use as input" fetches a signed URL and runs the normal upload.
- **Submission:** `/api/jobs` and held jobs share `queue_job`; upscale and recipe jobs build their own graph and share the tail, `submit_graph`, so progress, the gallery and push work for all of them. `POST /api/jobs/check` reuses `prepare_job`.
- **Job store:** `DATA_DIR/jobs.sqlite3`, one row per job with an in-memory copy for reads (a pre-0.8 `jobs.json` is imported once and renamed `.migrated`). Mutations serialize with an RLock (one uvicorn process). It keeps the newest `MAX_JOBS` (5000) non-favourite jobs; favourites are never evicted. New records save `params` and `run_details` (effective values only, never the option lists), returned as `details`; legacy records may lack both. Job inputs are served by authenticated job/index lookup only; bounded WebP previews live in `DATA_DIR/inputs`.
- **Watcher and push:** `watch_jobs` (started in `lifespan`) wakes on the progress websocket's end-of-prompt events (`ProgressTracker.ended`, else every `WATCH_INTERVAL` s), runs `check_watched`, which checks `/history` for unfinished jobs, stores the `job_summary`, keeps a WebP thumbnail of the cover image and sends Web Push. `/outputs` answers finished jobs from the store and `/view?thumb=1` serves the stored thumbnail, so the gallery survives ComfyUI restarts (ComfyUI keeps history in memory only). A failure on one job is logged and the pass goes on. A job neither queued nor in history for `LOST_MISSES` passes over at least `LOST_AFTER` s (ComfyUI restarted) is marked `lost` with a push; past `WATCH_FOR` (24 h) it is marked lost regardless. Push only posts to the browser vendors' push hosts (`PUSH_HOSTS`), never to arbitrary client URLs, and drops subscriptions that return 404/410. Web Push needs HTTPS.
- **Live progress (`progress`):** `listen` keeps a websocket to ComfyUI's `/ws` as `CLIENT_ID` (the id jobs are queued under, since ComfyUI sends progress only to that client; a second connection with the same id replaces the first). `ProgressTracker` keeps step counts per prompt and the latest preview frame, which binary frames attribute to the currently executing prompt. `/api/jobs` registers each prompt's sampler nodes (`expect`), so status reports `pass`/`passes` (two-pass Wan runs), drops stale steps once another node runs, and sets `finishing` after the last sampler. Previews only arrive if ComfyUI's live preview method is on.
- **Stream:** `GET /api/jobs/stream?ids=` (SSE, defined before `/api/jobs/{prompt_id}` so the route wins) sends each open job's state (`pending` + position, `running` + `progress.status`, `done`, `missing` after 3 history misses, `offline`) on change and at least every 2 s, for up to `STREAM_FOR` s. `queue_snapshot` shares one `/queue` call per second across streams, the watcher and `/api/jobs/outputs`, and sorts pending items by number (ComfyUI returns heap order). The phone reads it with `fetch` (EventSource can't send the Bearer header) via `MobileTools.sseEvents`, and falls back to polling `/api/jobs/{id}/progress` (`pollLoop`) after 3 failed streams; it fetches `/preview` when `frame` changes.
- **Queue:** `GET /api/queue/jobs` lists running/pending in order; jobs not in the job store show only "Started outside the app". `POST /api/queue/{id}/next` (app jobs only) deletes the pending item and re-posts its prompt with `front: true` and the same `prompt_id`, refusing if it started or already ran in between; if ComfyUI assigns a new id, `JobStore.rekey` follows it.
- **Cancel / free:** `/api/jobs/{id}/cancel` deletes a pending job, or interrupts it only if it is the running one (older ComfyUI ignores `prompt_id` on `/interrupt` and would stop anything). `/api/comfy/free` asks ComfyUI to unload models.
- **Held jobs (`deferred.py`):** on `ComfyOffline`, `/api/jobs` returns 503 `{offline, can_hold}` and `/api/uploads` keeps the photo in `DATA_DIR/held/` (`held: true`). `POST /api/deferred` stores validated `Job` bodies (no adviser tokens, only `mobile_*` images) and optionally sends WoL; `run_deferred`/`start_deferred` queue them once `/system_stats` answers, uploading held photos first (`send_held_uploads`). Failures are marked `failed` with a push. Max 50 held, kept 3 days. Recipe jobs can't be held.

## Gallery, presets, snippets

- **Library:** `/api/library/jobs` (paginated) takes `q`, `workflow`, `favorite` and returns `workflows`; `POST /api/library/jobs/{id}/favorite`, `DELETE /api/library/jobs/{id}`, `POST /api/library/jobs/bulk` (`favorite|unfavorite|remove`). Removing deletes the record, thumbnail and input previews, never PC files.
- **Detail screen:** gallery taps use `openGalleryPhoto` and fetch fresh signed output URLs without switching to the Create tab. The full-viewport dialog shows metadata, pages through files, optional comparison, video playback and a link to the job card.
- **Presets (`preset_store.py`):** SQLite CRUD with transaction-protected writes, maximum 100 presets / 64 KB each. `/api/presets` persists full settings snapshots without uploaded filenames; `/validate` checks live options before the UI loads one.
- **Snippets:** `PresetStore` has a `snippets` table (names `[A-Za-z0-9][A-Za-z0-9_-]{0,39}`, case-insensitive unique, 200 max). `MobileTools.expandPrompt` expands `__name__` (one random line of a multi-line snippet, 5 levels deep) then `{a|b}` innermost first, once per run on the phone.

## Settings check, AI adviser, AI image review, prompt help

- **Settings check:** `settings_check.check(graph, controls)` runs fixed per-family rules over the final job graph via `POST /api/jobs/check`, so it sees exactly what Generate sends. It needs no AI or setup. Unknown families get no family advice. Rules: LoRA/model family mismatch, duplicate LoRAs, strength > 1.5, speed models (turbo/lightning/DMD/`Nstep`) with too many steps or CFG, SD1.5/SDXL step, CFG and size ranges, and Pony score tags. Fixes are offered only on plain `KSampler` fields that `find_controls` exposes. Bundled workflows should produce no issues at their defaults; keep it that way when adding rules. The phone runs it on Generate when "Check settings before generating" is ticked (per device), skips it under an adviser approval, and a failed check never blocks the job.
- **AI adviser (`adviser.py`, `adviser_ai.py`, `adviser_store.py`, `research.py`; see `docs/adviser.md`):** edits only the base KSampler's steps/CFG/sampler/scheduler and LoRA picker strengths (`field: 'strength'`), and only when one model feeds it through loaders, LoRAs and the plain model patches in `adviser.PATCHES` (PAG, SAG, FreeU, RescaleCFG). The AI is told each pass's LoRAs and patches, detailers, and for each file LoRA Manager's base model, strength tip and a settings excerpt of the creator's Civitai description (`adviser_library` in main.py; `/api/lm/{checkpoints,loras}/model-description`). Web research goes through SearXNG to `research.SOURCE_HOSTS`. A checkpoint's description is also local evidence: `Adviser._library_card` runs the same quote-verified fact extraction as web research, so proposals work without SearXNG. Reviews are cached in `DATA_DIR/adviser.sqlite3`.
- **AI image review:** `POST /api/jobs/{id}/vision-review` sends one image output of that job (checked against `outputs_for`, fetched as `preview=jpeg;90`), the prompt it was made from (`vision_prompt`: typed or reviewed prompt, trigger words, the job's printed captions, negative prompt) and the job's `details` to the provider's optional `vision_model` (`Adviser.vision`, `AI.review_image`, strict `ImageReview` schema). Results are cached per file and model in memory. It may suggest base-sampler `steps`/`cfg` (null keeps them). The viewer offers applicable fixes as ticked options and "Run again with fixes" (`MobileTools.withVisionFixes`): prompt words go onto the typed prompt, the reviewed caption, or `caption_suffix`; negative words extend the negative prompt only when the workflow exposes one; steps/CFG go to the base sampler. Same seed by default. Shown only when `/api/adviser/status` reports `vision_configured`, saying whether the image leaves the PC.
- **Prompt help:** `POST /api/prompt/enhance` (text model) and `/api/prompt/describe` (vision model, a `mobile_*` upload read back from ComfyUI's input folder) return `{prompt}`. `PROMPT_STYLE` picks tags, phrases or sentences from the checkpoint name; `model_label` strips PC folders before it goes to the provider.

## Upscale and recipes

- **Upscale:** `POST /api/jobs/{id}/upscale` takes one of that job's saved images (`type: output`) and queues `workflow_jobs.upscale_graph`: `LoadImage` of `<subfolder>/<file> [output]` (ComfyUI reads its own output folder, nothing is uploaded) → `UpscaleModelLoader` + `ImageUpscaleWithModel` → lanczos `ImageScaleBy` to 2× or 4× when the model's factor (from its name) differs → `SaveImage` `mobile/upscale`.
- **Recipe sync:** `recipes.RecipeSync` copies LoRA Manager's `/api/lm/recipes` list (normalized by `recipes.normalize`, at most 500) and each recipe's preview image to `DATA_DIR/recipes/` every minute, independent of the workflow sync. A 404 means LoRA Manager isn't installed, and the previous copy is kept. Model Librarian mirrors its recipes into LoRA Manager, so this is the only source.
- **Recipe graphs:** `build_graph` produces CheckpointLoaderSimple → LoraLoader chain → optional CLIPSetLastLayer (clip skip) → CLIPTextEncode ×2 → EmptyLatentImage → KSampler → VAEDecode → SaveImage (`mobile_recipe`). Models resolve to a unique ComfyUI option by the file name of LoRA Manager's `localPath` first, then by name stem; recipe names often differ from file names. A missing or ambiguous checkpoint/LoRA fails with the names. A1111 sampler names (`DPM++ 2M Karras`) map to sampler + scheduler, and an unknown sampler falls back to euler with a note.
- **Recipe API:** `GET /api/recipes` hides PC paths and signs image URLs (`/api/recipes/{id}/image`, HMAC like job views). `POST /api/recipes/{id}/jobs` takes optional `seed`/`prompt`/`negative`. The phone keeps `recipeId` on the job for Run again / Same seed.

## Conventions

- Keep security posture conservative. The service is meant for a trusted LAN or Tailscale network only, and new endpoints should be authenticated and must not leak ComfyUI user-data beyond workflow `.json` names.
- The version string lives in `VERSION` in `main.py` (used by FastAPI and `/api/health`); the README title repeats it.
- `.env` lives on the NAS and must never be committed. Pushes to `main` publish `ghcr.io/rpeters1430/comfy-mobile:latest` and `v*` tags are published too. Renovate manages pinned dependencies, the action SHAs and the base image digest.
- `python tools/check_workflows.py` converts every workflow against `fixtures/object_info.local.json` (gitignored; refresh with `curl -o fixtures/object_info.local.json http://100.77.144.56:8188/object_info` over Tailscale). The bundled workflows are stale against the current PC (see `docs/roadmap.md`); many need models or custom nodes it no longer has. `--trim` writes `fixtures/object_info.bundled.json`, the committable snapshot the CI test uses: the repo is public, so it keeps only node classes the bundled workflows use and file names they already contain. Never commit the raw `object_info.local.json`. A `LoraLoaderModelOnly` left on `None` is bypassed (mode 4) in the files rather than special-cased in the converter.
- Nodes the app inserts are named `mobile_*`; `node_settings` skips them.
